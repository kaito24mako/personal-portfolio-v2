# Design and Development

Building with Next.js

- I chose Next.js not only because I was still in the beginning stages of learning the Next.js framework, but because there are various optimizations that it provides for a high-performance website. For example, prefetching occurs in which a route utilizing the <Link> component is pre-fetched and pre-rendered before the user navigates to it, making the portfolio site feel instant and responsive. And inside of all the JavaScript being loaded upfront in traditional single-page applications, only the code needed for the current route is loaded, making initial load time much faster. Although it may be excessive for a small application like mine, these reasons still justify a valid change from using React for my portfolio v1 to using Next.js for the v2.

Incorporating TypeScript

- This was the first project in which I utilized TypeScript. As most web-based job listing require an understanding of TypeScript, I figured I would practice it in this project. Essentially, TypeScript enables explicit type-setting in JavaScript objects and variables, future-proofing the site and providing a smoother debugging process. Throughout my project, I created explicit TypeScript classes very excessively, which I understand isn't necessary as in most cases TypeScript will automatically classify types depending on what values you give to variables and properties. However, for the purpose of learning, I explicitly outlined every class type.
